# MP 客户雷达维护

## 描述
客户档案维护和热度评分更新服务。每次拜访后自动更新客户档案、重新计算热度评分、标记关键事件。

## 触发条件
- 手动触发：当用户说"更新客户档案"或"记录拜访"时
- 手动触发：当用户说"客户 {客户名} 有 {事件描述}"时

## 工具依赖
- GitHub CLI (`gh`) 或 Git 命令行
- 环境变量：`GITHUB_TOKEN`

## 执行步骤

### 1. 拉取最新客户数据
```bash
cd ~/.openclaw/workspace/mp-team-data
git pull origin main
cat data/customers.json
```

### 2. 解析用户输入
用户可能用自然语言描述拜访情况，例如：
- "今天拜访了东莞匠运，确认了ALS-040ARN的报价，客户有意向下单"
- "浙江芯晖有人事变动，新采购经理上任"
- "青岛宝丽金的样品已交付，等待测试反馈"

从输入中提取：
- 客户名称（模糊匹配到 18 家客户之一）
- 拜访日期（默认今天）
- 拜访内容
- 结果/下一步

### 3. 更新客户档案
根据提取的信息更新对应客户的档案：

**添加拜访记录**：
```json
{
  "id": "自动生成",
  "date": "2026-06-04",
  "content": "报价确认",
  "outcome": "客户有意向下单",
  "nextAction": "发送正式报价单"
}
```

**更新热度评分**：
根据以下维度重新计算 0-100 分：
- 拜访频次（20%）：最近拜访时间越近分数越高
- 意向度（25%）：根据拜访结果评估
- 预算规模（20%）：年用量/订单金额
- 竞品替代窗口期（20%）：现有竞品问题/合同到期
- 人事变动（15%）：关键决策人变化

**标记关键事件**：
- 如果提到"人事变动"，添加标签 "人事变动"
- 如果提到"样品"，添加标签 "样品测试中"
- 如果提到"报价"，添加标签 "待报价"

### 4. 沉睡客户唤醒检测
扫描所有客户：
- 如果客户 heatLevel 为 "sleeping" 且标签包含 "人事变动"
- 输出提醒：
  ```
  💡 唤醒机会: {客户名} 近期有人事变动，建议重新接触
  当前热度: {score}分
  上次拜访: {date}
  ```

### 5. 保存并推送
```bash
git add data/customers.json
git commit -m "customer: 更新 {客户名} 档案 $(date '+%Y-%m-%d %H:%M')"
git push origin main
```

### 6. 输出结果到终端
```
=== 客户档案更新完成 ===
客户: {客户名}
新热度评分: {旧分} → {新分}
新增拜访记录: 1条
新增标签: {标签列表}
下一步行动: {nextAction}

沉睡客户唤醒提醒: {N}条
{列表}
```

## 热度评分规则
| 分数范围 | 等级 | 颜色 |
|---------|------|------|
| ≥80 | 高热 | 红色 |
| 60-79 | 温热 | 橙色 |
| 40-59 | 低温 | 蓝色 |
| <40 | 沉睡 | 灰色 |

## 注意事项
- 客户名支持模糊匹配，如"匠运"匹配"东莞匠运精密"
- 每次更新后自动重新计算所有客户的热度排名
- 历史拜访记录不删除，追加到 visitHistory 数组
